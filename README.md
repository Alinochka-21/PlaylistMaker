15 спринт: 
Основные моменты:

- В SearchActivity:
  - Для взаимодействия с сервером используются:
        1)TrackDto (единица информации в виде трека с сервера десериализуется в объект этого класса)
        2)Response (код с сервера приходит в объект этого класса)
        3)TracksSearchResponse (если запрос выполнен успешно и response.body не пустой, то в этом объекте будут храниться все пришедшие TracksDto)
        4)TracksSearchRequest (отвечает за отправку содержимого запроса)
        5)SearchResult (хранит два состояния - успех и ошибку)
  - interface iTunesApi - метод работы с сервером, просто получить содержимое с сервера в формате Response 
  - интерфейс NetWorkClient - факт отправки запроса 
  - RetrofitNetworkClient() - логика того, что мы получаем после отправки запроса (если мы отправили объект не того формата - не TracksSearchRequest - ошибка на стороне клиента),
  иначе приходит объект Response() или TracksSearchResponse(), внутри находится код состояния, взависимости от которого дальше варьирует логика 
  - interface TracksRepository - факт получения успеха/ошибки
  - TracksRepositoryImpl - наложили бизнес-логику, то есть прописали процесс передачи данных из TrackDto в Track (чтобы домен-слой не знал как работает дата-слой с сервером) и
  обозначили, что в случае успеха мы получаем объект, внутри которого содержится список Треков, а в случае ошибки - выходит объект, содержащий код ошибки
  - interface TrackInteractor - факт успешного запроса или получения ошибки (для перехода из домен-слоя в ui)
  - TrackInteractorImpl - выполняем запрос в фоновом потоке, а затем в зависимости от результата работаем с разными объектами + вернулись в текущий поток, потому что
  будем реализовывать изменения ui - элементов 
  - в Creator создаем метод получения объекта репозитория, чтобы получить объект интерактора
  - В самой активити создаем метод отправки запроса (performSearch) на сервер, где вызываем объект интерактора и у него же через анонимный объект прописываем логику изменения экрана при успешном запросе и в случае получения ошибки 
  - Аналогичным образом (только без взаимодействия с сервером) прописано получение списка треков из SharedPref, добавления туда новых треков, и очистка списка
  
- В SettingsActivity:
